# Vani v1.2.2 — P(-1) sweep, structural close-out

**Date**: 2026-08-20
**Version audited**: 1.2.2 (patch — no API change, pin unchanged at `6.5.32`)
**Parent audits**: [`v1.2.0`](2026-08-20-v1.2.0-audit.md) (the sweep) ·
[`v1.2.1`](2026-08-20-v1.2.1-audit.md) (its code-level tail)
**Kernel baseline**: running kernel `7.1.8-arch1-3`

The last instalment of the 1.2.0 P(-1) sweep. 1.2.1 closed the seven items that were
just edits; what remained needed a **design decision**, which is what this release makes.

---

## The decision: a policy seam, not a mock

The sweep's largest open finding was blunt — XRUN recovery, suspend/resume and the
disconnect path had no coverage and **no way to get any**, because reaching them requires
a kernel that returns `-EPIPE` / `-ESTRPIPE` on demand. It was not a gap anyone had been
lazy about; it was a gap that assertions structurally could not reach. The sweep said so
and stopped there.

That gap was not academic. Two of 1.2.0's defects lived in it: `VANI_ERR_DISCONNECTED`
was produced by no path at all, so an unplugged device was classified as *recoverable*
and re-prepared in a loop; and `vani_play_from_ring` consumed the ring before writing, so
any short write or XRUN destroyed audio. Both sat there for many releases.

**Decision: split the classification from the transport.** `_vani_recovery_for(xfer_result,
state)` is now a pure function; `vani_play` and `vani_record` classify through it and then
act. The classification — which is where both of those defects lived — is tested
exhaustively. The residue is roughly six lines per direction that issue prepare/resume and
retry, and that residue is stated rather than hidden.

**A mockable ioctl indirection was considered and rejected.** It would put an indirect
call on the transfer path and a DCE-defeating global into code that cyrius-doom,
polyomino, bb and mishran vendor into games — a cost paid by every consumer to test a
path none of them can trigger differently. The full reasoning, the alternatives, and the
conditions under which this should be revisited are in
[ADR 0004](../adr/0004-recovery-policy-seam.md).

## Also closed

### `snd_interval` open/empty flags were declared and never read

`AlsaIntervalFlag` has existed since v0.2.0. Nothing consulted it, so every interval was
treated as the closed range `[min, max]`. ALSA uses `openmin` / `openmax` to mean the
endpoint is **excluded**, and `empty` to mean the device supports nothing in that
dimension at all.

The consequence was the negotiate defect the sweep filed: `vani_format_negotiate` clamped
a request onto `min` or `max` without checking whether the device had just excluded that
exact value, returning `Ok` for a format that `HW_PARAMS` then rejects.

Now `_hwp_interval_lo` / `_hwp_interval_hi` honour the open bits, `_hwp_interval_clamp`
returns −1 for an empty or inverted interval — a real "cannot" rather than a bogus pick —
and `_hwp_interval_contains` (which existed but was kept alive only by its own test)
honours them too.

**What this does not fix**, stated plainly: a *jointly* unsupported combination can still
slip through. Each dimension is clamped independently, and nothing re-refines with the
chosen rate/channels/format together, so `HW_PARAMS` can still reject a triple whose parts
are individually legal. Fixing that needs a second `HW_REFINE` round-trip, which cannot be
verified without hardware — so it was **not** added on the principle that an untested
second ioctl in a frozen public function is worse than the bug it targets.

### `FIRST_MASK == 0` was an implicit dependency

Six mask call sites passed the param number straight in as a mask index while the twelve
interval sites explicitly subtract `FIRST_INTERVAL`. Made symmetric.

Cost measured rather than assumed: same unreachable-fn count (1317), same NOPed bytes
(356,709), same `R+E` segment size (`0x067598`) — 21,301 bytes differ, but it is the same
quantity of code laid out differently. Worth keeping because it buys robustness a test
cannot: were `FIRST_MASK` renumbered, the subtraction adapts, while an assertion on the
resolved slot values would still pass and the un-subtracted sites would silently address
the wrong mask.

### Dead code and gates

`_clamp` removed — dead in production once negotiation moved to `_hwp_interval_clamp`.
CI's distlib drift gate extended to the `.deps` sidecars, and verified to fire on a
tampered one.

## Coverage

**852 → 893 assertions. Reference coverage 109/109 (100%), 8/8 files.**

A caveat on that number, because it is the kind that flatters: `cyrius coverage` counts a
function as referenced if a test *mentions* it. One function (`vani_err_print_name`)
reached 100% on a mention alone, so it was given an actual call. All **140** `src`
functions are now genuinely invoked from `tests/`, not merely named.

### Mutation testing found a defect in this release's own work

Every new group was mutation-tested. That caught something worth recording: a test named
`test_recovery_disconnected_outranks_suspended` **passed with the checks reordered**.

Kernel states are distinct scalars and the branches are mutually exclusive, so there is no
precedence to assert — the test was tautological, and the source comment claiming the
ordering was "deliberate and asserted" was simply false. This is the same defect class the
1.2.0 sweep found in the old `AlsaFormat` assertions, reintroduced by the person who
documented it.

Both corrected: the comment now says the ordering is a readability choice, and the test
was replaced with one that pins what actually matters — each action is produced by exactly
one state — which does kill a collapse mutant (4 failures).

Mutants killed, by group:

| Mutation | Failures |
|---|---|
| Retry on an unknown state instead of failing | 14 |
| Treat a short write as a failure | 10 |
| Confuse the OPENMIN bit with the INTEGER bit | 9 |
| Shift the mask base by 4 | 9 |
| Ignore `openmin` | 7 |
| Ignore `openmax` | 5 |
| Collapse GONE into RESUME | 4 |
| Treat an empty interval as usable | 1 |

### Benchmarks — measured by the method the 1.2.1 audit prescribed

That audit concluded a **same-session A/B against the previous tag** should be the default,
after two releases running where a benchmark "regression" turned out to be machine drift.
Applying it:

| Benchmark | 1.2.1 (same session) | 1.2.2 |
|---|---|---|
| `ring_200ms_playback` | 84,735 / 83,838 ns | 83,065 / 83,444 |
| `ring_write_64b` | 167 / 167 ns | 167 / 161 |
| `hwp_init_any` | 918 / 937 ns | 945 / 905 |
| `hwp_interval_set_exact` | 9 ns | **9 ns** |
| `negotiate_format_pick` | 10 ns | 10 ns |

No regression; flat to slightly better. The last row also **retires a claim from the 1.2.1
audit**: it reported "+1 ns" for the range guard added to `_hwp_interval_set_exact`,
hedged as "at the resolution limit". Measured properly, it is 9 against 9 — that +1 ns was
noise too.

## What remains

Nothing from the 1.2.0 sweep is still open. Carried forward as new items:

| Item | Note |
|---|---|
| The prepare→retry **sequence** is still untested | Narrowed from the original gap but real; ADR 0004 states it and the condition for revisiting |
| `vani_format_negotiate` does not re-refine jointly | Needs a second `HW_REFINE`; not addable without hardware to verify it |
| **No real-hardware verification across the whole 1.2.x line** | `/dev/snd` is EACCES for this shell (logind ACL grants `sddm`). Enumeration works under yukti 2.3.8 and every program degrades closed, but nothing has been played. Last audible confirmation: cyrius-doom 0.30.5, 2026-06-29. Several defects fixed across 1.2.0-1.2.2 sit on paths only real playback exercises. |

That last row is the honest headline for the 1.2.x line: a lot of real defects were found
and fixed by reading, probing and mutation, and **none of it has been heard**.

**Not vani's**: `dhvani` does not build (pre-existing, `http_body`), still vendors vani
1.0.0, and its `rt-safety.md` annotates `vani_play_from_ring` "no alloc" — false until
1.2.0, true now.
